## 修复「提示运行成功但实际没启动」(worktree: ../openlearn-manager-wt-startup, 分支 fix/start-verification)

根因：`src-tauri/src/process_manager.rs::start_service` 只要 `cmd.spawn()` 成功就置 `is_running=true` 并 `Ok(())`，
完全没等 npx 真正拉起服务。npx 下载包慢 / CLI 报错 / 端口被抢都会表现为「显示运行中但打不开」。

改动要点（已提交 fa2c114）：
- 启动改为轮询探测 `127.0.0.1:<port>` 是否开始监听（500ms 间隔，上限 180s），就绪才 `is_running=true`；就绪前保持 `is_starting`
- 子进程在就绪前退出 → 返回含退出码 + 最近 15 行输出的明确错误；超 180s 同样报错并终止进程
- 新增 `ProcessState.recent_output`（`append_output` / `tail_output`）用于失败回溯
- `build_start_command()`：优先用 Node 同目录的 npx 绝对路径 + 注入 PATH；`detect_node` 增加 nvm/volta/常见路径兜底
- Unix：`cmd.process_group(0)` + `kill -TERM/-KILL -<pgid>` 整组回收（npx 被杀后 node 子进程会变孤儿继续占端口）
- `stop_service` 结束后 `wait_port_release(port)` 校验端口真释放
- 前端 HomePage：用 `opMode`(idle/start/stop) 代替单一布尔，展示真实等待秒数，失败信息 `whitespace-pre-wrap` 不截断

环境备忘：
- worktree 里 `pnpm install` 会报 `EPERM futime`（沙箱限制），可临时 `ln -s` 主仓 node_modules 后跑 `tsc --noEmit` 做类型检查
- `cargo check` 在 worktree 首次约 2 分钟，无警告
- 判定子进程是否存活别用 `kill -0`，僵尸会误判；要 `wait()`/`poll()` 回收后再判

## openlearn-next CLI 真实形态（v0.7.8，下载 cli.mjs 实测确认）——重要，别再写错

- **没有 `start` 子命令**。启动服务 = 无子命令 + 选项：
  `npx openlearn-next@<ver> -p <port> -H 127.0.0.1 [--db-path x]`
  传 `start` 会被当未知位置参数 → `错误: 未知命令: "start"` → exit 1。
- **默认端口 9000**（不是 3000）；默认 HOST 0.0.0.0；默认 DB `~/openlearn-next/data.db`。
- `backup <file>` / `restore <file>`：文件路径是**位置参数**，不是 `--output`
  （写 `--output` 会报 `未知选项`）。`backup` 另有 `--full`。
- `reset-admin [-P <pwd>]`：**不指定密码时随机生成**，不再默认 admin，新密码打印在输出里。
- 其他子命令：`doctor [--fix|--compat-report]`、`compat-report`、`check-update`、
  `migrate [status|rollback]`、`plugins [list]`、`clean/clean-cache [--npx|--db|--all]`。
- 启动后 cli.mjs 会 spawn `node dist/server.cjs` 并转发 SIGINT/SIGTERM，
  **保底 35s 强制退出** —— 所以「停止后等端口释放」不能只等几秒（本项目设为 15s）。

验证技巧：不必真跑服务。`npm pack openlearn-next@<ver>` 后只解出
`cli.mjs + cli-*.mjs + scripts/assert-node-runtime.mjs`，直接
`node cli.mjs <args>` 就能验证参数解析（会因缺 dist/server.cjs 报「服务执行产物未找到」，
但只要没报「未知命令/未知选项」就说明参数形态正确）。
